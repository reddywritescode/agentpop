# AgentPop product acceptance matrix

> Archived pre-convergence matrix. This file preserves the broader historical
> audit, including surfaces that were subsequently removed from the product.
> The authoritative image-first release contract is
> [`customer-release-matrix.md`](customer-release-matrix.md). Do not use the
> credit, Services, Applications, or separate-agent rows below as current
> product requirements.

This is the release contract for the open-source product and the hosted
`agentpop.cloud` service. A screenshot or rendered page is not a pass. A row
passes only when the user control changes durable control-plane state and, where
applicable, the data plane demonstrates the resulting behavior.

Status vocabulary:

- `PASS`: verified against the running local stack.
- `PASS-LIVE`: verified against a real Linux/KVM or third-party provider.
- `FAIL`: missing, fake, broken, or contradicted by runtime evidence.
- `PARTIAL`: metadata/UI exists, but an important production behavior is absent.
- `SKIP-LIVE`: implementation can only be proved with a Linux/KVM host or a
  real third-party credential/account.
- `PENDING-UI`: API path is covered; browser control evidence is still pending.

The machine evidence is generated by `scripts/verify-product.sh` in
`docs/acceptance-evidence/latest.json`. Browser evidence is generated by the UI
audit in `docs/acceptance-evidence/ui/`.

## Release rule

Local open-source release is acceptable only when all non-live rows are `PASS`
or explicitly documented `PARTIAL` limitations. Hosted beta additionally
requires production auth, tenant isolation, real Composio OAuth/invocation,
template builds, network enforcement, storage mounts, durable database/queue,
billing, and a Linux/KVM Firecracker proof run.
